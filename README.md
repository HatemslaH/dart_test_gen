# dart_test_gen

Генератор юнит-тестов для Dart: по одному или нескольким файлам (или каталогам) под `lib/` создаются зеркальные `test/<...>/<имя>_test.dart` с вызовами методов класса. Ожидаемые результаты берутся **снимком** — при генерации код реально выполняется во вспомогательном процессе, а в тесты подставляются литералы (`expect(actual, expected)`).

## Возможности

- Разбор API через **analyzer**: публичные методы экземпляра, простые параметры (`int`, `double`, `bool`, `String`, `List<int>`, enum из того же файла, зарегистрированный паттерн `RgbColor`).
- Граничные комбинации аргументов (декартово произведение наборов значений для каждого параметра).
- Успешные кейсы: `final <параметры> …`, затем `expected`, `actual`, `expect(actual, expected)`.
- Если при снимке метод бросает исключение — генерируется тест с `throwsA(isA<…>())`.
- Выбор класса: по умолчанию берётся класс с **наибольшим числом** подходящих методов в файле; иначе можно указать `--class`.

## Запуск

Из корня пакета (где лежит `pubspec.yaml`):

```bash
dart pub get
dart run bin/generate.dart lib/usecases/calculator.dart
dart run bin/generate.dart lib/usecases/data_toolbox.dart
dart run bin/generate.dart lib/usecases -v
```

Несколько целей за раз (каждый файл — в **отдельном изоляте**, генерация параллельная):

```bash
dart run bin/generate.dart lib/usecases/calculator.dart lib/usecases/data_toolbox.dart
```

Каталог под `lib/` (рекурсивно все `.dart` только внутри этого дерева после фильтра):

```bash
dart run bin/generate.dart lib/usecases
```

Указать класс явно (если в файле несколько классов) — **только если на выходе ровно один** `.dart` файл:

```bash
dart run bin/generate.dart lib/usecases/foo.dart --class Foo
```

Выходные тесты **повторяют относительный путь** под `lib/` → под `test/`: например  
`lib/usecases/foo.dart` → **`test/usecases/foo_test.dart`**.

**Прогресс по умолчанию:** одна строка на `stdout` (полосы и проценты по каждому файлу, `\r` + сброс строки), сразу с первого кадра; после завершения добавляется перевод строки.

**Подробности:** `-v` или `--verbose` — этапы и пути уходят в **`stderr`** (формат `[относительный-путь-под-lib]\tфаза\t…`), прогресс остаётся на `stdout`.

Всё выводится через `stdout`/`stderr.write`, без `print`.

После генерации:

```bash
dart test
```

## Пример цикла разработки

1. Реализуете или меняете класс, например `lib/features/my_service.dart`.
2. Запускаете `dart run bin/generate.dart lib/features/my_service.dart` (или папку).
3. Просматриваете или коммитите `test/features/my_service_test.dart`.
4. При смене поведения снова запускаете генератор и обновляете снимки (или правите код под уже зафиксированные ожидания).

Снимок кодирует **текущее** поведение: если вы исправляете ошибку в реализации, тесты начнут падать, пока не перегенерируете их или не обновите ожидания осознанно.

## TODO / дорожная карта

Приоритет выше → делать раньше.

1. **Ограничение и выбор кейсов.** Сейчас полное декартово произведение границ быстро раздувает тесты для 3+ параметров. Нужно: лимиты, sampling, свой YAML/CLI с явными наборами или только happy-path сценарии.

2. **Nullable и значения по умолчанию.** Параметры `int?`, опциональные и именованные аргументы — не поддерживаются; границы для nullable (в т.ч. `null`) не выводятся из AST.

3. **Async / `Future` / `Stream`.** Методы с асинхронным телом или возвратом `Future`/`Stream` отфильтровываются; нужны `async` тесты и корректный снимок (или осознанный отказ с диагностикой).

4. **Расширение типов.** `Set`, `Iterable`, обобщения кроме `List<int>`, пользовательские классы без специальной ветки в снимке (сейчас есть договорённости для enum, `Map<String, int>`, `RgbColor`). Варианты: `toJson`/конвенция, плагинные правила на тип, или ручной «адаптер» снимка.

5. **Статические методы, factory, extension types.** Сейчас только нестатические методы обычного класса.

6. **Геттеры, сеттеры, операторы.** Не покрываются; для геттеров нужна отдельная модель «вызова» в тесте.

7. **Устойчивость чисел с плавающей точкой.** Для некоторых `double` возможны хрупкие сравнения; опционально генерировать `closeTo` / epsilon.

8. **Конфигурация и DX.** Файл конфигурации (пути, исключить методы, переопределить границы по имени метода), единый `dart_test_gen`-бинари вместо только `generate.dart`, лучшие сообщения об ошибках при несовпадении снимка и компиляции раннера.

9. **CI и детерминизм.** Документировать зависимость снимка от SDK/платформы; при необходимости — флаг «dry-run без записи» и сравнение с эталоном.

## Лицензия и структура проекта

- `bin/generate.dart` — точка входа CLI.
- `lib/` — парсинг (`source_parser.dart`), снимок (`snapshot.dart`), шаблоны тестов (`test_generator.dart`), оркестрация (`generate_pipeline.dart`).
