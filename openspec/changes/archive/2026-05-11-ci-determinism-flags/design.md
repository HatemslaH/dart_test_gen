## Context

Сгенерированный тест начинается с двух волатильных строк: заголовка `// Auto-generated by dart_test_gen` (стабильная) и таймстампа `// Сгенерировано: <ISO-8601>` (нестабильная — меняется при каждом запуске). Существующий `writeTestFile(testOut, content)` всегда пишет файл; пайплайн в `generateSingleLibraryFile` (`lib/generate_pipeline.dart`) собирает `content` и затем вызывает запись. Чтобы поддержать `--dry-run` и `--check`, нужно (а) пробросить флаги до точки записи, (б) при `--check` нормализовать таймстамп перед сравнением.

Параллельно в коде `lib/` есть 112 строк с русским текстом в комментариях, разбросанных по 8 файлам. Это refactor без поведения — отдельная подсекция.

## Goals / Non-Goals

**Goals:**
- `--dry-run`: ноль изменений на файловой системе под `test/`, exit `0` при успехе, exit `1` при ошибке пайплайна. Стdout: список путей, которые **были бы** записаны.
- `--check`: ноль изменений под `test/`, exit `0` если контент совпадает (после нормализации таймстампа), exit `1` если есть расхождения, exit `1` если файл-эталон отсутствует. Stderr: краткий diff-summary (путь + первые ≤10 расходящихся строк).
- Документировать SDK/platform-зависимость снимка в README, привести пример CI.
- Перевести `//` / `///` комментарии в `lib/` на английский без изменения смысла. Идентификаторы, строки, public API — не трогать.

**Non-Goals:**
- Полноценный `diff` (с unified-format'ом). Достаточно «первая расходящаяся строка + контекст».
- Переводить пользовательские CLI-сообщения и лог-строки (отдельная задача про i18n).
- Туллинг для синхронизации generated tests как pre-commit hook — оставляем CI-only.

## Decisions

### D1. Где включать флаги

`--dry-run` и `--check` парсятся в `parseCliArgs` как `bool?` поля и добавляются в `GeneratorConfig` через top-level флаги (а не как per-method). Конфликт `--dry-run && --check` валидируется в `generateFromCli` сразу после парсинга: `CliLog.err(...)`; `exit(64)`. В YAML их **не** добавляем — это CI-инструменты, место им в командной строке.

Альтернатива: один флаг `--mode=write|dry-run|check`. Отклонено: два простых булева понятнее в скрипте CI и в `--help`.

### D2. Нормализация таймстампа

Заводим `String stripGeneratedTimestamp(String content)` в `lib/test_generator.dart` рядом с тем местом, где таймстамп пишется. Функция вырезает строку, начинающуюся с `// Сгенерировано:` (regexp с literal-префиксом). Используется и при сравнении, и в будущем — например, в тестах самой утилиты. После перевода комментариев на английский (см. ниже) баннер заменим на `// Generated:` — функция нормализации тогда будет матчить оба префикса (`Сгенерировано` для legacy и `Generated` для нового), чтобы `--check` против старых файлов оставался стабильным.

Альтернатива: убрать таймстамп вовсе. Отклонено — он полезен при ручном code review генерируемого файла.

### D3. `--check`: формат вывода

При расхождении пишем в stderr:

```
[check] differs: <test/path/foo_test.dart>
  expected: <abs path of existing file or "<missing>">
  first diff at line <N>:
    -- existing: <truncated old line>
    ++ generated: <truncated new line>
```

И в конце суммарно `[check] N file(s) differ`. Exit `1` если хотя бы один файл расходится; иначе `0`.

### D4. Перевод комментариев — стратегия

Полностью автоматический перевод (sed по regexp) опасен — есть многострочные `///` блоки, ссылки на идентификаторы. Делаем вручную по файлам, минимальной правкой:
- сохраняем форму комментария (`///` остаётся `///`),
- сохраняем ссылки на идентификаторы (`[ParamType]`, `EmitGenerationUi` и т.п.),
- не трогаем русские пользовательские строки в коде (внутри литералов `'…'`).

Объём — 112 строк/8 файлов — небольшой; правки точечные.

### D5. README раздел «CI и детерминизм»

Краткий чек-лист:
1. Пин SDK в CI (`actions/setup-dart@v1` с конкретной версией).
2. Включать `use_close_for_double: true` для double-возвратов, чтобы сгладить IEEE-754 разницу.
3. Прогон `dart run dart_test_gen lib/ --check` как стейдж CI; пример YAML.
4. Зависимость снимка от рантайм-имён ошибок — упомянуть, что `_AssertionError` / `_TypeError` нормализованы (ссылка на нашу таблицу).

## Risks / Trade-offs

- **[R1] `--check` упадёт после любого расширения `test_generator`.** → Это и есть желаемое поведение: CI ловит «забыли перегенерировать». Документируется в README.
- **[R2] Перевод комментариев меняет git blame.** → Однократная цена; альтернатив нет.
- **[R3] Лоулевел: `// Сгенерировано:` теряется, есть `.gitignore`-стиль защиты.** → Нет, файл идёт в коммит. Просто фиксируем оба префикса в нормализаторе.
- **[R4] Параллельные изоляты при `--dry-run` всё ещё пишут временный snapshot runner в `${TMP}/dart_test_gen/`.** → Это допустимо: `--dry-run` гарантирует только отсутствие изменений в `test/`, временные артефакты по-прежнему очищаются по тем же правилам, что и сейчас (включая `--keep-runner`).

## Migration Plan

1. Добавить флаги в `parseCliArgs` и в `GeneratorConfig` (топ-уровень, `dryRun`/`check`).
2. В `generateSingleLibraryFile` — после генерации content, ветка на режим:
   - default: `writeTestFile(testOut, content)`.
   - `--dry-run`: `CliLog.out(testOut)` (и при `verbose` — content в stderr).
   - `--check`: сравнить с диска (после `stripGeneratedTimestamp` с обеих сторон); собрать diff-summary и пометить ошибку.
3. На уровне `generateFromCli` агрегировать exit-код check'а: при наличии хотя бы одного расхождения — exit `1`.
4. Реализовать `stripGeneratedTimestamp` в `test_generator.dart`; покрыть юнит-тестом.
5. Прогнать перевод комментариев в `lib/`: 8 файлов, точечные правки.
6. Поменять баннер `// Сгенерировано:` на `// Generated:` в `generateTestFile` и `// Auto-generated by dart_test_gen` (или эквивалент по-английски, если есть RU-вариант). Проверить, что `stripGeneratedTimestamp` принимает оба префикса.
7. Дописать README раздел «CI и детерминизм» и пометить TODO #9 как `[x]`.
8. Прогнать `dart test` — все существующие тесты + новый юнит на `stripGeneratedTimestamp` + smoke на `--dry-run` и `--check` — должны быть зелёными.

Rollback: удалить флаги/диагностику, восстановить `writeTestFile` и баннер. Перевод комментариев можно оставить — он независим.

## Open Questions

- Стоит ли в `--check` дополнительно проверять, что **существующий** файл — наш генерат (по заголовку `// Auto-generated`)? Полезно, чтобы не «затирать» ручные тесты. Решение: фиксируем поведение «сравнение по содержимому, и если файл существует и не начинается с auto-generated banner — печатаем warning и считаем расхождением». Это и в дизайне отражено.
